# Архитектура Traffic Limit

## Слои

- `lib/models` — неизменяемые модели статистики, интерфейсов и процессов.
- `lib/services` — мониторинг, сохранение параметров, журналирование, трей и связь с native service.
- `lib/widgets` — общие карточки, переключатели и состояния интерфейса.
- `lib/pages` — отдельные русскоязычные экраны приложения.
- `windows/native/TrafficLimitService` — C++ Windows Service, SCM lifecycle, named pipe и счётчики `GetIfTable2`.
- `installer` — Inno Setup master с UAC, ярлыками, autorun и uninstall.

## Поток данных

1. Flutter раз в секунду получает агрегированные счётчики адаптеров Windows через PowerShell.
2. Разность двух измерений преобразуется в Кбит/с, а абсолютные счётчики — в МБ/ГБ.
3. Лимиты сохраняются в `SharedPreferences` и передаются службе через `\\.\\pipe\\TrafficLimit`.
4. Служба с WinDivert перехватывает пакеты, применяет token bucket и повторно отправляет их с рассчитанной задержкой.
5. Ошибки прав, отсутствия службы или драйвера показываются пользователю и пишутся в лог.

## Принципы

- Безопасный fallback: без подписанного kernel driver приложение не делает вид, что ограничивает скорость.
- Все пользовательские тексты и инструкции — на русском языке.
- Компоненты разделены по ответственности, native service не смешан с UI.
